# 근거 기반 작성 기준 v1.0

확인일: 2026-10-15 (Asia/Seoul). 제품 기준 ID: `fitnote-evidence-1.0`.

## 결론

자소서의 내용 근거는 **공식 공고와 지원자 본인의 기록**입니다. 논문은 사실을 추적하고 질문을 설계하는 방법을 뒷받침합니다. 논문을 인용했다고 개인의 경력이나 채용 적합성이 입증되지는 않습니다. 현재 기준은 핏노트가 연구를 참고해 설계한 제품 정책이며, 통계적으로 검증한 자소서 평가 척도가 아닙니다. 가중치·종합 점수·합격 예측을 만들지 않습니다.

## 여섯 기준과 동작

| 기준 | 필요한 기록 | 실제 자동 검사 | 사람이 확인할 부분 |
|---|---|---|---|
| 출처 | 본인 기록, 선택적 문서 위치·자료 링크, 본인 검토 표시 | 출처 번호 존재·원문 보존 | 사실 여부, 자료의 진위·본인 소유·기밀 |
| 개인 역할 | 팀 전체 과제와 본인의 책임 | 역할·행동 항목 입력 여부 | 성과의 주체, 공동 작업의 기여 범위 |
| 행동·이유 | 직접 구현·비교·검증한 행동 | 기술 키워드는 후보 연결만 제공 | 대안·트레이드오프, 기술 설명의 정확성 |
| 결과·확인 방법 | 테스트·측정 조건·피드백·회고 | 원문에 없는 수치 후보 표시 | 같은 환경의 전후 비교인지, 정성적 결과의 근거 |
| 공고 연결 | 공고 항목, 경험 ID, 본인이 적은 연결 이유 | 공고 문구가 바뀌면 기존 연결의 인정 해제 | 실제 업무와 경험의 관계, 해석과 공식 요건의 구분 |
| 주장별 대조 | 초안 문단과 당시 근거 스냅샷 | 원문과 문자 일치·수정·누락·가짜 번호 구분 | 바꾼 표현의 의미, 복합 문장의 개별 주장 |

‘원문 일치’는 사실 인증이 아닙니다. 허위인 자기기록도 그대로 인용하면 문자상 일치할 수 있습니다. 수정 문장이 올바른 의역이어도 자동 통과시키지 않습니다. 정량 성과를 강제하지 않으며 미측정·실패·정성적 학습을 보존합니다. 단위 변환이나 계산으로 새 지표를 자동 생성하지 않습니다.

## 연구와 공식 자료

### 직무를 먼저 이해하기

[미국 OPM, Job Analysis](https://www.opm.gov/policy-data-oversight/assessment-and-selection/job-analysis/)는 업무, 필요한 역량, 둘 사이의 관계를 직무분석의 대상으로 설명합니다. 이를 공고 항목과 프로젝트의 연결 이유를 기록하는 설계에 적용했습니다. 한국 기업의 실제 선발 기준이나 배점으로 가져오지 않습니다.

[OPM, Structured Interviews](https://www.opm.gov/policy-data-oversight/assessment-and-selection/structured-interviews/)는 직무 관련 과거 행동·가상 상황을 일관된 질문과 기준으로 살피는 방법을 설명합니다. 면접 연습의 내 기여·선택 이유·결과 확인 질문에 참고했습니다. STAR 형식이 모든 자소서에서 우월하거나 합격률을 높인다는 주장으로 사용하지 않습니다.

### 주장을 작게 나누기

[Min et al. (2023), FActScore, EMNLP](https://aclanthology.org/2023.emnlp-main.741/)는 생성문을 원자적 사실로 나누어 지식 출처가 뒷받침하는지 평가합니다. 긴 글 전체를 한 번에 ‘좋다’고 승인하지 않는 설계에 참고했습니다. 본 연구는 주로 인물 소개를 다루므로 채용 맥락에 그대로 일반화할 수 없습니다. 현재 앱은 문단 단위 문자 대조를 제공하며, 논문의 원자적 사실 분해·검색·NLI 모델과 FACTSCORE 점수를 재현하지 않습니다.

### 인용의 품질 따로 보기

[Gao et al. (2023), ALCE, EMNLP](https://aclanthology.org/2023.emnlp-main.398/)는 인용을 포함한 생성의 유창성·정확성·인용 품질을 평가합니다. 문장이 자연스러운 것과 근거가 맞는 것을 분리하는 설계에 참고했습니다. 현재 앱은 문단별 출처 스냅샷과 대조 결과를 제공하며, ALCE의 자동 평가 모델·인용 recall/precision을 실행했다고 표시하지 않습니다.

### 근거 부족을 별도로 남기기

[Thorne et al. (2018), FEVER, NAACL](https://aclanthology.org/N18-1074/) 및 [공식 데이터셋 설명](https://fever.ai/dataset/fever.html)은 Wikipedia에서 만든 185,445개 주장을 근거와 함께 분류합니다. 지지·반박 외에 정보 부족을 별도로 다루는 개념을 참고했습니다. 핏노트는 의미상의 참·거짓을 자동 판정하지 않으므로 상태를 ‘원문 일치 / 원문과 다름 / 직접 확인 필요 / 출처 오류 / 작성 필요 / 예시’로 정의했습니다.

## 데이터셋 후보와 라이선스

| 후보 | 용도 | 확인한 조건 | 현재 사용 |
|---|---|---|---|

| O*NET® 31.0 | 직업·기술·업무활동 사전 후보 | [공식 DB](https://www.onetcenter.org/database.html): 다운로드 데이터 CC BY 4.0, 출처·라이선스·변경 고지 필요. API 약관과 구분 | 데이터 미수집. 앱 기술 사전은 자체 작성 |

O*NET 데이터는 미국 직업을 설명하므로 한국 공고보다 우선할 수 없습니다. 공개된 타인의 이력서나 합격 자소서는 공개 여부와 개인정보·저작권·상업 이용 가능성이 별개이므로 이번 구현의 학습 재료로 쓰지 않았습니다. 연구 데이터가 있다고 한국어 개발자 자소서의 합격 예측을 만들 수 있는 것도 아닙니다.

HQ Tech의 공개 소개를 요약해 기술로 업무 문제 해결, AI 활용의 본인 검증, 희망 전문 분야의 경험이라는 **핏노트의 준비 방향**을 만들었습니다. 이는 공식 평가 척도·필수 기술 요건이 아닙니다. React·Python·C++ 등의 필수 요건을 임의로 추가하지 않았습니다. 세부 직무·조직은 채용 결과에 따라 결정된다고 안내합니다.

Tech 링크 뒤에는 약관 동의와 지원서 화면이 있어 동의·지원·개인정보 제출을 진행하지 않았습니다. 따라서 실제 자소서 문항·글자 제한·상세 평가 문항은 수집하지 않았습니다. 앱 기본 문항을 공식 문항으로 표시하지 않습니다. 현재 사용자의 실제 경험도 제공받지 않았으므로 예시 프로젝트는 계속 예시로 유지합니다. 일정·내용은 이후 바뀔 수 있으며 지원 전 공식 페이지에서 다시 확인해야 합니다.

## 생성과 문서 처리

기본 초안은 원문 인용입니다. 선택한 기업·직무·제목으로 만드는 연결 문장은 별도 유형이며, 실제 경험의 증명으로 세지 않습니다. `〔E1〕` 같은 검토 표시는 복사·Markdown 내보내기에서 제외됩니다. 근거 보고서 JSON과 버전에는 당시 원문·기준 버전·공고·연결 이유를 보존합니다.

AI 서버는 [OpenAI 공식 Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)를 사용하도록 구현했습니다. 구조화 출력 자체가 사실을 보증하지 않으므로 **모델은 기존 사실 ID의 순서와 보충 질문만 반환**합니다. 본문은 클라이언트가 저장 원문으로 구성합니다. 예시·미확인 경험, 없는 ID·중복·누락을 거부합니다. 키와 모델 설정 전에는 호출하지 않으며 실제 AI 실행처럼 표시하지 않습니다. API 실행에는 별도의 API 프로젝트와 서버 비밀 설정이 필요합니다.

PDF.js와 Mammoth로 문서를 브라우저 안에서 텍스트 추출합니다. HTML 결과를 주입하지 않습니다. PDF 페이지·DOCX 문단을 보존하되, 편집한 문장이 원문에 없으면 이전 문서 위치를 붙이지 않습니다. SHA-256은 같은 파일인지 확인할 지문일 뿐 내용의 진실성 증명이 아닙니다. 스캔 OCR·표의 완전한 순서 복원·외부 링크의 내용 검증은 지원하지 않습니다. 추출 후 사람이 프로젝트 후보와 STAR 항목을 검토합니다.

## 검증의 범위와 다음 실증

자체 작성한 한국어 개발 사례로 수치 부풀림, 주체 변경, 새 기술, 부정문 반전, 가짜 인용, 인용 누락, 복합 문단, 예시 오용, 출처 변경, 서버 입력과 인증 경계를 검사합니다. 이것은 기능 회귀 테스트이며 실제 지원서 품질 측정이나 공개 데이터셋 평가 결과가 아닙니다.

다음 실증에서는 지원자가 동의한 기록만 사용해, 두 명 이상의 검토자가 주장과 근거를 독립 표시하고 불일치를 조정해야 합니다. 합의한 정답으로 인용 정확성·빠진 근거·허위 수치·수정 문장의 의미 보존을 별도로 평가합니다. 유용성은 사용자가 근거를 찾는 데 걸린 시간과 수정 횟수로 먼저 확인합니다. 채용 결과와의 관계는 개인·기업·직무 차이가 커 별도의 연구 설계 없이는 인과 효과로 주장하지 않습니다.
