# 핏노트 제품 설계와 공개 화면 분석

2026-10-15 (Asia/Seoul) 확인. 외부 서비스의 공개 소개와 제공된 데모 계정 화면을 직접 관찰했습니다. 접근 제한을 우회하거나 비공개 소스·검사 문항·디자인 자산을 수집하지 않았습니다.

## 참고 서비스에서 관찰한 내용

[Arda 프로젝트](https://event.wanted.co.kr/ai-championship/2026/projects/297)는 채용 담당자용 지원자 통합 관리·채용 에이전트로 설명합니다. 공고 자격·우대·인재상 기준 서류 평가, 이력서·자소서 요약, 맞춤 질문, 서류와 답변 일치 요약, 채용 상태 변경·메일 흐름을 소개합니다. Whisper 기반 음성 분석과 ViT·MediaPipe 표정 데이터 시각화를 명시하지만, 공개 소개만으로 그 분석의 타당성이나 실제 합격 결정에 미치는 영향을 검증할 수는 없습니다. 공개 페이지에는 조회 시점 1위, 512가 표시되어 있었습니다. 순위는 변동될 수 있습니다.

[지원자 데모](https://seuk.suvisdev.cloud/my)는 지원 현황, 먼저 해야 할 일, 인적성 검사, 면접 시간 선택, AI 면접으로 구성됩니다. 데모의 성향 설문은 1~5점 응답 방식이며, 선택 사항임을 안내했습니다. 데모 설문은 열람만 했고 응답·제출하지 않았습니다.

[JOBDA](https://www.jobda.im/)의 공개 화면은 역량검사, 개발자 검사, 면접 연습 및 기업별 질문 탐색을 제공합니다. 정확한 현행 평가 항목·가중치와 ‘얼굴 때문에 점수가 결정된다’는 주장은 이번 공개 자료만으로 확인하지 못했습니다. 핏노트의 검사 문항·문제·기억 연습은 자체 제작했으며, JOBDA의 결과와 호환되지 않습니다.

## 지원자에게 전환한 기능

| 채용 담당자의 작업 | 핏노트에서 지원자의 작업 |
| --- | --- |
| 지원자 서류 요약 | 프로젝트를 STAR 형식으로 재사용 가능한 경험으로 정리 |
| 공고 기준 지원자 평가 | 공고 키워드에 대해 본인이 설명 가능한 경험 근거를 찾기 |
| 서류 기반 면접 질문 | 프로젝트의 선택 이유·대안·결과를 연습하는 질문 |
| 전형 단계 관리 | 기업별 준비 상태·마감·자소서 버전 관리 |
| 성향·면접 데이터 | 자기이해와 답변 연습 기록; 채용 점수화하지 않음 |

차별점은 글을 대신 써 주는 것보다 ‘같은 프로젝트를 어느 기업에서 어떤 논점으로 설명할지’를 근거와 함께 관리하는 것입니다. 경험 → 공고 요구사항 → 초안 → 예상 꼬리질문을 연결해 매번 배경을 다시 설명하는 부담을 줄입니다.

## 현재 엔진의 계약

키워드 사전은 React, TypeScript, 성능, 사용자 관점, 협업, Python, DB, API, 테스트, 문제 해결, 인프라, Java/Spring입니다. 공고에서 탐지된 키워드와 경험 텍스트의 겹침을 보여 줍니다. 문맥 이해가 없으므로 ‘경험 없음’ 같은 부정문도 단어 일치로 연결될 수 있고, 근거는 반드시 사용자가 확인해야 합니다. 겹치는 키워드 수는 적합도나 합격률이 아닙니다.

초안은 선택한 경험의 상황·역할·행동·결과를 그대로 보존하며, 누락 항목과 지원동기·기여 연결은 대괄호 안내로 남깁니다. 수치·경력·기업 정보를 생성하지 않습니다. 예시 데이터는 각 화면에 표시하고, 실제 지원용 내용으로 교체하도록 안내합니다.

## 다음 구현 순서

1. **실제 AI 연결:** 서버 측 API에만 비밀키를 보관합니다. 경험·공고의 입력 ID를 포함하는 구조화 응답으로 요구사항, 근거 인용, 누락 정보, 초안과 주장 출처를 받습니다. 초안의 모든 성과·수치가 입력 근거에 존재하는지 검증합니다. 근거가 없으면 질문으로 반환합니다. 프롬프트 인젝션에 대비해 공고·이력서 내용은 지시가 아닌 데이터로 분리합니다.
2. **포트폴리오 가져오기:** PDF/DOCX 텍스트 추출, GitHub 공개 저장소 선택 가져오기, 프로젝트별 분리와 사용자 검토. 파일별 출처·페이지·커밋을 유지합니다.
3. **개발 직무별 전략:** 프론트엔드·백엔드·데이터·인프라 기준 확장. 단순 기술 언급과 실제 구현, 본인의 역할, 검증 가능한 결과를 구분합니다.
4. **면접 코칭:** 명시적 동의 아래 음성 전사, 실제 발화 시간·속도·군더더기 같은 관찰 지표를 제공합니다. 얼굴로 성격·정서·채용 적합성을 추정하지 않습니다. 녹화가 필요하면 저장 범위·보존 기간·삭제를 사용자가 선택합니다.
5. **서비스 운영:** 사용자 인증, 암호화된 개인 데이터베이스, 동기화, 내보내기·삭제, 배포 환경 분리, 비용·사용량 제어. 현재 localStorage를 실서비스 보안 저장소로 그대로 사용하지 않습니다.
6. **검사 고도화:** 새로운 자체 문제 풀과 난이도 조절, 접근성, 반복 학습 효과 표기. 타당화 연구 없이 심리적 특성·직무 적합도·합격률을 주장하지 않습니다.

구현 규모를 확장하기 전 첫 검증 질문은 ‘지원자가 이미 쓴 포트폴리오를 다시 설명하지 않아도, 다른 공고에 맞는 경험과 문항 구조를 유용하게 고를 수 있는가’입니다.
